# Open decision: the licence for generated benchmark data

**Status: unresolved.** This document records a decision that has *not* been
made, so that the gap is visible rather than silently implied. It deliberately
recommends no licence and offers no legal conclusion — that is the project
owner's decision to make, with advice if they want it.

Tracked by the follow-up issue *"Select and document generated benchmark-data
licence"*.

## What is already settled

The **source code** in this repository is under the MIT Licence (`LICENSE`).
That covers the generators, the CLI, the tests and the tracked configuration —
everything a contributor writes.

## What is not settled

Whether the **data those generators emit** — a truth graph, a file estate, an
observed state, an evaluation report, a published benchmark bundle — is governed
by the same licence, by a data-specific licence, by a public-domain dedication,
or by something else entirely.

The question is genuinely open rather than merely unwritten. A benchmark that is
published, cited and compared against is exactly the kind of artefact whose terms
people need to be able to read before they rely on it.

## The current position, as stated in the artefacts

The position is recorded consistently and without over-claiming, in three places:

* `README.md` — a "Licensing" section stating that the code licence is MIT and
  that generated-data licensing is not separately designated.
* Every built bundle's `LICENSES.md`, generated by
  `bundle/builder.py::_render_licenses`, which states the same to a consumer who
  has only the bundle and not the repository.
* Every bundle manifest, which carries the machine-readable field
  `"generated_data_license": "not-separately-defined"`.

"Not separately defined" is a factual statement about the project's position. It
is not an implicit grant, and it should not be read as one.

## What must change once a licence is selected

The intent is that the choice can be dropped in without restructuring anything.
In order:

1. **`src/dataswamp_biosystems/bundle/builder.py`** — `_render_licenses()`
   renders the notice text, and `_licensing_block()` sets the manifest field
   `generated_data_license`. Both are single functions with no other callers.
2. **A licence text file**, if the chosen licence needs its full text shipped —
   add it at the repository root beside `LICENSE`, and include it in the bundle
   through the same `SECTION_BUNDLE` mechanism `LICENSES.md` already uses.
3. **`README.md`** — replace the "Licensing" section's open-decision wording.
4. **`docs/bundles.md`** — the licensing paragraph describing what a bundle
   carries.
5. **This document** — replace it with the decision and its rationale, or delete
   it and record the outcome in an ADR under `docs/adr/`.
6. **`CHANGELOG.md`** — note the designation. Changing the terms under which
   already-published bundles were distributed is a user-visible change, so it
   belongs in a release entry, not a quiet edit.
7. **The bundle schema version** — if `generated_data_license` moves from a free
   string to a constrained vocabulary, that is a schema change and needs
   `BUNDLE_SCHEMA_VERSION` bumped and the fixtures regenerated.

Note that steps 1 and 7 change bundle *bytes*, and therefore bundle
fingerprints. Bundles are not covered by the golden digest contract, so no
golden digest needs regenerating — but any bundle fingerprint quoted in
documentation will change and must be requoted.

## Constraints the decision should respect

Not recommendations — just facts about this project that a decision has to fit:

* No third-party licensed dataset is included or referenced, so there is no
  inherited obligation to accommodate.
* The generated data contains no real patient, personal, employer, partner or
  proprietary content, so there is no privacy or confidentiality constraint.
* Bundles are designed to be published and cited, so the terms must be legible to
  someone holding only a bundle directory.
* The manifest field is machine-readable, so whatever is chosen should have a
  stable, unambiguous identifier.

## Explicitly out of scope here

* Recommending a specific licence.
* Drafting licence wording.
* Asserting what any licence would or would not permit.
