# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
the project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Two things are versioned separately and matter more than the package version to
anyone consuming output: the **on-disk schema versions** (truth, estate,
observed, prediction, evaluation, bundle) and the **generator versions**. A
change to either alters generated bytes, so it is called out explicitly in the
entries below.

## [Unreleased]

### Added

- **Reference baseline agents.** Three small, readable benchmark participants
  published so a result has something to be compared against: `null` (claims
  nothing — the recall floor and specificity ceiling), `naive-metadata` (shallow
  single-field signals) and `rule-based` (20 of the 41 defect rules
  re-implemented against observed metadata). New commands `dataswamp
  run-baseline` and `dataswamp list-baselines`; `run-baseline --evaluate` scores
  through the ordinary evaluator rather than a second scoring path. See
  [docs/baselines.md](docs/baselines.md).
- **Published canonical baseline scores**, pinned by
  `tests/baselines/fixtures/baseline-scores.json` and regenerated deliberately
  with `scripts/update_baseline_scores.py --confirm --reason ...`. Runtime is
  reported in the documentation rather than pinned, because it is
  machine-dependent.

### Notes

- Baselines are scored as genuine participants: each reads `observed-graph.json`
  and nothing else. The boundary is structural — one module opens one file — and
  is covered by tests that run every agent in a directory from which the ground
  truth has been deleted, that record every path opened during a run, and that
  reject a hard-coded canonical identifier anywhere in the package.
- No schema, generator version or golden digest changed. The baselines are new
  consumers of existing artefacts; they generate nothing.
- Two rules, `GOV-STALE-REVIEW` and `LIF-STALE-ASSET`, are documented as
  under-specified from observed metadata alone. No registry change was made.
- The baselines are **not** production-quality governance agents, and no LLM
  provider integration ships in this milestone.

## [0.1.0rc1] — 2026-08-03

First release candidate. The end-to-end benchmark workflow is complete: generate
a synthetic data estate, derive a defective observed view of it with a published
answer key, score a submission against it, package the result as a portable
bundle, and export it as catalogue metadata — all deterministic and offline.

This is the first version intended for people other than the author, so the
entry below describes the whole surface rather than a delta.

### Added — benchmark generation

- **Canonical company model.** A fictional oncology company — programmes,
  studies, teams, people, ownership, stewardship and eight controlled
  vocabularies — authored as versioned YAML under `config/` and validated by
  typed Pydantic models. `dataswamp validate-config`.
- **Deterministic truth graph.** The complete, correct synthetic scientific and
  governance state generated from that model: subjects, biospecimens, assays,
  instrument and pipeline runs, files, datasets, data products, contracts,
  quality checks, governance records, intended-use records, training approvals
  and lineage. Emitted as canonical JSONL shards with a per-shard-digest
  manifest. `dataswamp generate-truth` / `validate-truth`.
- **Scientific file estate.** Small but genuinely readable files for the truth
  graph's assets — H5AD, Parquet, OME-TIFF, PNG, VCF, BED, GeoJSON, Matrix
  Market, FASTQ, CSV/TSV/JSON/JSONL/YAML, gzip — with explicitly declared
  placeholders and sidecars for heavy binaries (BAM, CRAM, DICOM, SVS, Zarr).
  Three profiles (`tiny`, `demo`, `stress`), path-safe and budget-capped writes.
  `dataswamp generate-files` / `validate-files`.

### Added — the observed state and its answer key

- **Imperfection engine.** A deliberately imperfect observed state derived from
  the truth graph by injecting defects from an in-code registry of **41 rules
  across 12 categories**, under six maturity profiles (`gold`, `mostly-good`,
  `typical`, `poor`, `catastrophic`, `demo`). It reads the truth graph from
  disk, checksums it, and verifies it is unmodified; it mutates only JSON copies
  and never the truth entities. `dataswamp inject-defects` / `validate-observed`.
- **Machine-readable ledgers.** Every injected defect is recorded with its
  before/after values, its expected finding, and its expected remediation —
  including the approval policy, approver role and whether the fix is automatic,
  manual or unavailable.
- **Control partition.** `controls.jsonl` names every asset and file left clean,
  with a strict reserved partition held out of every rule's eligible population
  before selection, so true negatives and precision are measurable and a
  flag-everything strategy is visibly penalised. Emitted and independently
  re-validated.
- **Rule and remediation contracts.** `rule-scope.jsonl` publishes each rule's
  population, eligible set, control exclusions and selected set, so a rule's
  denominator is its declared population rather than the whole estate.
  `dataswamp list-defects` / `validate-defects`.

### Added — evaluation

- **Versioned prediction contract** (`schema_version: 1`) with a total
  validator. Three expressible claims — `finding`, `clean` and `abstain` — so an
  abstention is recorded and reported rather than folded into a confusion-matrix
  cell it did not earn. It asks only for what an agent could know from the
  observed graph.
- **Deterministic scorer.** `dataswamp evaluate` produces confusion-matrix and
  remediation reports, byte-identical for identical inputs. Scoring is
  pair-level on `(entity_id, rule_id)`; a prediction against an entity outside a
  rule's population is reported as an out-of-scope false positive rather than
  widening that rule's denominator.
- **Five separate dimensions** — finding detection, control preservation,
  remediation correctness, approval reasoning and non-remediation correctness —
  reported separately, with no weights and no composite score. Undefined metrics
  are emitted as `null` alongside their numerator and denominator, never as
  `0.0`.
- Read-only with respect to every other layer: it consumes emitted artefacts and
  never regenerates or rewrites ground truth.

### Added — distribution

- **Versioned benchmark bundles.** `dataswamp build-bundle` packages emitted
  layers into one portable, self-describing directory: a versioned manifest
  declaring every content file, SHA-256 checksums covering the manifest in turn,
  environment provenance, and licensing and schema notices. Truth-only,
  truth+estate, with-observed and complete-with-evaluation bundles are all
  first-class. A bundle is a directory rather than an archive, deliberately, to
  avoid archive-header nondeterminism.
- **Total verification.** `dataswamp verify-bundle` checks the manifest,
  structure, provenance and every checksum by exact recomputation, reporting
  every failure with the file and the invariant it broke. Nothing is written.
- **Stable streaming reader.** `BundleReader` verifies then streams; no layer is
  ever loaded whole into memory.

### Added — DataHub adapter

- **Offline metadata export.** `dataswamp export-datahub` emits the Metadata
  Change Proposals DataHub's `file` source ingests, plus a ready-to-run recipe
  that reads credentials from environment variables. No server, token or network
  is involved, and **no DataHub package is a dependency** — the adapter emits the
  documented payload shapes directly.
- **Privilege boundary.** `--mode observed` is built from `observed-graph.json`
  *alone* — never the findings, remediations, controls, rule scope or mutation
  log — which is the structural guarantee against truth leakage. `--mode truth`
  is privileged and marked as such in tags, custom properties and the export
  manifest.
- The mapping is pinned by committed fixtures, so a change cannot pass
  unnoticed, and the adapter is the only place in the project a catalogue is
  named.

### Added — release surface (new in this release candidate)

- **`dataswamp demo`** — the whole workflow into one directory: generate, score,
  bundle, verify and export, in a couple of seconds, with no seed, credential or
  network. Byte-identical across runs.
- **Example submissions** under `examples/predictions/` — `perfect`, `partial`
  and `unsafe` — with documented scores for each, plus a Python API example.
- **Packaged configuration and examples.** The canonical `config/` tree and the
  example submissions now ship *inside* the distribution, so an installed
  package can generate a benchmark without a source checkout.
- **Documentation for first contact**: a rewritten README, `docs/public-api.md`
  (stable / experimental / internal / unsupported), `docs/release-checklist.md`,
  `docs/roadmap.md`, `CONTRIBUTING.md`, `SECURITY.md` and this changelog.

### Reproducibility

- Same config, generator version and seed produce byte-identical output.
- Across the whole declared dependency range, the truth graph and the
  observed-state ledgers are byte-identical. The materialized estate is
  byte-identical only within one **environment fingerprint**, because its binary
  payloads are written by pyarrow, Pillow, tifffile and anndata. The claim is
  made per-artefact rather than globally.
- Provenance carries no wall-clock value, hostname, username or path.
- The contract is pinned by committed golden digests, verified in CI on Python
  3.12 and 3.13 against both the locked and the lowest-direct dependency
  resolutions. **The golden digests are unchanged in this release candidate.**

### Known limitations

- The canonical scenario is deliberately small (180 catalogue assets, ~1 800
  lineage edges): a correctness benchmark, not a load test.
- One estate shape and one defect taxonomy — no difficulty tiers, adversarial
  scenarios, cross-asset defects or near-miss controls yet.
- No reference baseline agents are published, so there is no established score
  to compare against.
- No run-to-run comparison or regression reporting.
- DataHub export is offline file emission; live ingestion and round-trip
  validation are not implemented. No other catalogue is supported.
- Scores are comparable only within one generator version, config fingerprint,
  profile and seed.
- **The licence for generated benchmark data is not yet designated** — see
  [docs/generated-data-licensing-decision.md](docs/generated-data-licensing-decision.md).
